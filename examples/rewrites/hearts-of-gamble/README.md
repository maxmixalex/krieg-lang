# Hearts of Gamble：完整玩法的 Krieg 语义重写

本工程用类型化 TypeScript、表、共享函数、TSX 和 `krg.css` 重写赌场入口、二十一点、猜大小、猜杯子和轮盘。游戏脚本由 Krieg 编译生成；源码不导入上游 PDX，不包含上游脚本字符串或通用 AST 搬运。图片、声音和原译文从用户提供的私有原模组恢复，公开工程不携带这些内容。

## 构建与复核

以下命令从仓库根目录运行。`../private-mods/Hearts-of-Gamble` 必须是用户提供的原模组；没有它时纯编译测试仍能运行，原作差分测试会明确跳过。

```sh
npm run build
node scripts/rewrite-inputs.mjs ../private-mods hearts-of-gamble
node dist/cli.js build examples/rewrites/hearts-of-gamble
node --test tests/native-not-semantics.test.mjs tests/decision-missions-stockpiles.test.mjs tests/rewrites-gamble.test.mjs tests/rewrites-uno.test.mjs
node scripts/compare-rewrite.mjs ../private-mods hearts-of-gamble --out examples/rewrites/hearts-of-gamble/build/comparison.json
node scripts/render-gamble-ui.mjs
```

成功构建生成 `build/mod` 和 `build/hearts-of-gamble.mod`。本次本地构建验证了 **439 个文件、19,372,487 字节**。项目的 `maxExpansion` 提高到 1,000,000，以容纳完整牌面和原生 UI 状态展开；这不是运行时游戏循环上限。

打包可以使用仓库的 `pack` 命令；整个项目的最终 CWT 检查与私有包由上层汇总流程执行。本 README 不将一次构建或解释器测试说成已经启动 HOI4。

## 独立差分 oracle

`tests/support/gamble-native-machine.mjs` 读取并解释**原作 PDX 与编译后的 PDX**，复用通用原生语法解释器，不导入本工程的牌表、赔率函数或结算函数。比较双方实际执行后的资源、装备、建筑与槽位、idea、变量、旗标、任务、事件以及声音序列。

`tests/rewrites-gamble.test.mjs` 的报告写入 `build/native-oracle.json`。本次共 **20,258 个比较用例**，包括：

- 58 种下注在零余额、恰好门槛、充足余额和重复下注时的可用性与扣款。
- 轮盘 49 种下注 × 37 个结果，共 1,813 个组合；事件选项和结算后的账目同时比较。
- 猜杯子的 3² + 5² + 7² = 83 个选杯／实际位置组合。
- 猜大小全部收手倍率；二十一点胜负、平局、保险及查牌分支。
- 二十一点 15 个发牌任务 × 6 种起始总点数 × 52 个随机分支，以及玩家六个要牌位置 × 5 种总点数 × 52 个随机分支；额外验证限制牌堆的 36 张牌和保险随机极值。
- 全部原始 GUI 可见／可用谓词：涉及旗标的全无、全有和单个成立状态，以及数值临界值。
- 实际任务推进、点击和事件结算的生命周期轨迹；关闭、重开、旧旗标遗留行为。

另有 `tests/decision-missions-stockpiles.test.mjs` 验证任务 API、装备严格门槛、建筑层数比较、辅助函数返回边界及音频并发限制；`tests/native-not-semantics.test.mjs` 验证多子项 `NOT` 是 NOR，并区别 `NOT { AND { … } }`。这次聚焦运行共 **25 个测试通过，0 失败**，包含已有 UNO 回归。

### UI 状态证据

`scripts/render-gamble-ui.mjs` 从两边的原生 GUI 与 sprite 定义读取布局，用同一解释器求可见性，再用真实 DDS 素材绘制七组并排状态：二十一点进行中／爆牌、猜大小收手、选杯／揭晓、轮盘 0／35。结果位于 `build/ui-projections/`，包含 `states.json`、各状态 PNG 和 `contact-sheet.png`。

这些图已用于检查牌位、背景、杯子和球以及轮盘结果的状态呈现，不止检查文件存在。它们是离线状态投影，**不是 HOI4 截图**；替代字体、基础游戏按钮贴图、引擎裁剪、动画时序和事件弹窗调度仍需游戏内验证。原译文包含大小写不同的变量占位符，投影器按精确大小写读取；不能凭投影中的数值断言引擎也同样处理。

## 完整对照报告

`build/comparison.json` 由 `scripts/compare-rewrite.mjs` 对实际构建生成，解析失败数为零。

| 类别           |  原作 |  生成 | 完全相同 | 有变化 | 缺项 | 新增 |
| -------------- | ----: | ----: | -------: | -----: | ---: | ---: |
| 原生定义       |   349 |   354 |      197 |    149 |    3 |    8 |
| 图片与声音文件 |   209 |   209 |      209 |      0 |    0 |    0 |
| 语言键         | 2,033 | 2,048 |    2,025 |      8 |    0 |   15 |

定义清点的三个缺项是内部音频 clip 名 `sound/chips_place`、`sound/card_dealt1`、`sound/card_dealt2`。`AudioBank` 将它们分别生成为 `chips_place_sound`、`card_dealt1_sound`、`card_dealt2_sound`；三项公开 soundeffect 标识及对应 WAV、音量、压缩与最大并发 1 保持一致。它们因此也出现在新增项中，另五项新增是供 TSX 与决议共用的命名 scripted effect。它们不是三段音频资源缺失。

149 个不同定义包括高层函数与表展开的脚本结构变化、贴图路径规范化和 UI 关闭／账目栏等变化。因此不能以“完全相同”列代替玩法验证，也不能把“有变化”全部等同于语义偏差；上面的独立 oracle 提供行为层证据。报告的定义分组层级不会逐个数出 idea，另有叶级测试确保 163 个全部保留。

### 译文的明确例外

原包的四份波兰语／简中菜单文件存在 8 个同名键值冲突，涉及二十一点和轮盘的开／关文案。随输入提供的官方 Wiki `Localisation` 的 Replacing 段没有承诺跨文件重名键的一致胜出顺序。恢复脚本因此明确选择主 `casino` 文件的菜单值，并将另一版本逐条保留为 `krg_gamble_alternate_<原键>`。这是有意消除上游歧义，**不能保证与所有原安装加载结果逐字相同**，但没有丢弃文本或语言键。

另外，原 `simp_chinese/casino_l_english.yml` 的实际 header 是简中，恢复时按 header 更正文件名。四份受影响输入均有 SHA 校验，所有操作集中在 `scripts/rewrite-inputs.mjs`，可重现而非手改私有素材。15 个新增语言键为 8 个保留别名及本工程 7 个 UI 标签。

## 写法为何更省力

原作游戏逻辑、GUI、sprite 和 sound 定义合计 **37 个原生文件、46,220 行**（19 个 txt、5 个 gui、10 个 gfx、3 个 asset）。本工程对应的类型化源码与样式为 **10 个文件、2,182 行**，按此统一口径减少约 **95.3%**；不把素材、译文、测试或编译产物混入源码统计。行数是格式化后实数，而不是压缩排版获得的指标。

三个具体维护例子：

1. **改赌注数量。** `resources` 一行定义通常数量与轮盘数量，`bets` 同时生成可用性和扣款；`payout` 用同一条记录结算。增加一种受支持资源不用分别修改 58 处按钮和各倍率分支。
2. **改牌面行为。** 52 张牌由 rank／suit 表生成，`draw` 负责权重、牌面旗标和声音，`scoreCard` 集中处理阶段差异。原作的 AH 和 2C 特例有显式条件，仍可单独审查和测试。
3. **改布局。** 牌位、杯数和下注账目由 TSX 表达式展开；条件使用同一 typed scope。新增关闭按钮调用与决议共享的函数，不另写一份重置脚本。

例如，库存条件把严格含义放在调用处：

```ts
c.hasEquipment("infantry_equipment", 999, "moreThan");
```

任务以 `mission: { days, activation, cancel, timeout }` 表达生命周期，不借用普通 `CountryAction` 的收费语义。SDK 类型及编译器都拒绝把 `mission` 混进 CountryAction，防止得到表面能编译却漏掉任务调度的决议。

本次落地的小型通用能力还有 `StateScope.buildingLevel`、资源数值查询、idea 内战可用条件、音频最大并发，以及辅助函数调用边界修复：运行时分支内调用辅助函数，函数内部的静态 `return` 不再误报逃出外层分支；函数自己在运行时分支提前返回仍拒绝，避免不正确的控制流展开。这些能力有独立正负例并登记在 `scripts/api-topics.mjs`。

## 交付边界

公开内容是本项目源码、测试、解释器和可复核恢复／比较／投影脚本。`original-assets`、构建目录与包含原素材的包是私有产物。当前证据支持完整源定义覆盖、已测分支的行为一致和可构建资源完整性；尚未通过实际 HOI4 客户端确认引擎字体、动画、弹窗时序以及与其他模组的组合效果。
