# Hearts of UNO：手工语义重写

这个项目从用户提供的 `Hearts-of-UNO.zip` 阅读规则后重新编写，全部游戏行为来自 `src/*.krg.ts` 与 `src/interface.krg.tsx`。它没有调用 `krieg import`，没有复制原生 `.txt/.gui/.gfx/.asset` 逻辑，也没有把原生树搬成大字典。原始图像、音频与作者已有的十语种本地化来自用户压缩包，由仓库脚本按固定 SHA-256 恢复；这些第三方数据不随源码仓库分发。

## 构建

从仓库根目录运行：

```sh
npm run build
node scripts/rewrite-inputs.mjs /path/to/mods.zip hearts-of-uno
node dist/cli.js check examples/rewrites/hearts-of-uno
node dist/cli.js build examples/rewrites/hearts-of-uno
node dist/cli.js pack examples/rewrites/hearts-of-uno
```

`build/` 包含原生模组目录、外部启动器 `.mod` 与可移植 ZIP。`node dist/cli.js world examples/rewrites/hearts-of-uno` 刷新编辑器声明；项目 `tsconfig.json` 可以用普通 TypeScript 检查。新增的抽牌提示提供英文与简体中文；原始界面提示与十语种词条使用同步后的原变量名。恢复脚本仅修正原文件缺少的行首缩进，不改译文键和值。

进入游戏后，在原 `UNO Game` 决议组里打开界面、由真人主持、加入五个席位或填入 AI、开始游戏。六名玩家依序点击牌堆各摸七张。原作允许在发牌期间打出普通牌、跳过、反转、+2 和 +4，只有万能换色牌在此阶段受限；重写保留这一边界行为。平常摸一张牌就结束回合；罚摸需逐张完成。牌堆耗尽时使用原洗牌决议。胜利事件确认后重置大厅。

## 源文件职责

| 文件                    | 内容                                                                             |
| ----------------------- | -------------------------------------------------------------------------------- |
| `src/cards.krg.ts`      | 4 色、13 种点数/功能、复制数规则和 8 张万能牌，生成 108 个物理牌标识             |
| `src/game.krg.ts`       | 大厅、六国席位、手动发牌、抽牌、出牌、方向、惩罚、颜色选择、洗牌、结果事件与重置 |
| `src/decisions.krg.ts`  | 保留原显示/隐藏、主持、五个加入席位、AI填充/移除、开局、洗牌、重置决议键         |
| `src/interface.krg.tsx` | 类型化框架与玩家组件、原始手牌坐标、六席视角、牌背、UNO 警示和点击行为           |
| `src/ai.krg.ts`         | 普通牌、万能牌、+4、选色与牌堆的原始 AI 优先级                                   |
| `src/display.krg.ts`    | 同步原作各席手牌数、罚摸数、剩余牌与发牌计数，保留十语种变量引用                 |
| `src/audio.krg.ts`      | 用 AudioBank 重新声明所有实际存在的 12 段音频                                    |

静态 `map/flatMap/filter` 组织规则表，`some/every` 将有限表条件合成原生逻辑；游戏中的手牌由原生数组保存。`For` 从牌规则表展开 108 个原始固定槽位，手牌数组决定各槽位的可见性。玩家组件从六席位置推导所有视角的国家标签、牌背和 UNO 警示，回调的国家作用域由 `GuiBindings<CountryScope>` 检查。`ScriptedWindow` 将每个控件的点击、可用、可见与 AI 权重绑定到其名称。`randomChoice` 以每张牌的原生变量权重生成 `random_list`，已抽出的牌权重为零。

## 尚未声称等价的部分

- **原始界面的重复名称已修正。** 第六视角的玩家五名称和 UNO 警示原本都叫 `player_6_p6p_uno`，且名称控件误用警示文案。组件为两者生成独立名称与正确的国家文案。原 `green_1_one` 与后续手牌共享 x=750 的坐标仍保留。相同桌面牌面合为一个图标，五个同位置牌堆合为一个操作入口，原位置和显示条件有原生对照测试。
- **AI 入席的调度方式改变。** 六席分配通过明确国家筛选完成；原作依靠带国家目标的加入决议和引擎的 AI 点击时序。GUI 的 117 个权重均有输入对照，但入席调度、多次退席后的原作残留旗标和引擎选取目标的时间未声明等价。
- **内部存储与随机序列改变。** 原作使用每张牌旗标和逐玩家全局计数，新实现使用手牌数组、整数席位/轮次与具名变量。抽牌仍按剩余物理牌权重，不保证原先“先选颜色、再选牌”两个随机调用与新单次抽牌得到相同 RNG 序列。不能在一局原版 UNO 的中途直接换用本模组继续该局。
- **原始缺失音频引用。** 原 `UNO_sounds.asset` 声明 `UNO/place_card.wav`，压缩包实际没有该文件。当前出牌调用实际存在的 `card_dealt.wav`，并保留原已使用的出牌音频行为；不会创建假素材。
- **真实客户端与多人调度尚未验收。** 已通过编译、普通 TypeScript、路径/本地化检查、原生脚本独立执行与打包；未在 HOI4 客户端验证绘制、原生 AI 调度、声音播放、联机同步或完整对局。

这些差异是本轮剩余工作清单，不能把通过的局部原生对照说成全部游戏行为或视觉完全等价。
