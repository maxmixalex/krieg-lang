# UNO 与赌场：同一玩法规则驱动多个操作入口

## Hearts of UNO 的牌表与六席界面

[UNO 工程](https://github.com/maxmixalex/krieg-lang/tree/main/examples/rewrites/hearts-of-uno)用颜色、牌值与副本数组织 108 张物理牌。抽牌读取各牌剩余的数量，手牌数组记录每个席位持有的牌。TSX 的 `For` 在编译时展开原始固定槽位，数组状态决定各槽位何时显示。`Player`、`Label` 和 `Hand` 组件从席位位置生成国家文案、牌背与 UNO 警示，点击和 AI 权重跟随对应控件声明。

玩法沿用六席大厅、逐次摸七张、初始功能牌只展示、洗牌时仅排除已持有牌、胜利事件确认后重置的顺序。原作在初始发牌阶段允许普通牌、+2 和 +4 按既有条件打出，万能换色牌另有限制，这些边界进入原生处理器对照。

| 对照内容                               | 实际检查                                       |
| -------------------------------------- | ---------------------------------------------- |
| 全部牌型、席位、方向、发牌和最后一张牌 | 5,664 项状态转移比较，包含声音顺序             |
| 出牌资格                               | 77,760 项原始与重写条件比较                    |
| 连续万能牌与选色                       | 384 项比较，包含连续 +4 的原始罚摸覆盖规则     |
| AI 权重                                | 56,106 项比较，覆盖原作全部 117 个权重入口     |
| 界面可见性                             | 39,852 项比较，覆盖六席牌背与 UNO 警示         |
| 几何与文案控件                         | 108 个手牌槽、359 个显示控件和 54 个去重桌面牌 |
| 本地化计数生命周期                     | 45 个状态检查点                                |
| 决议顺序、文案与效果封装               | 13 项原始元数据比较                            |

重复控件名称由组件生成的独立名称修正，同位置重复牌面合并为共享控件。内部手牌存储和随机调用次序有调整，进行中的原版 UNO 存档需要结束当前局后再切换。测试执行解析后的原生脚本，实际客户端绘制、声音播放和多人同步仍需游戏内验收。完整复现入口与差异记录位于工程 README。

## Hearts of Gamble：改一种下注资源要检查什么

[赌场工程](https://github.com/maxmixalex/krieg-lang/tree/main/examples/rewrites/hearts-of-gamble)把可下注资源、各玩法是否接受、扣费和赔付放在资源目录与经济函数中。轮盘将下注选项与 37 个落点分开，杯子用难度表，高低牌用奖励分级，二十一点单独处理保险、软 A 和庄家阶段。界面用同一批模型生成按钮、赌注显示与可操作条件。作者仍要决定资源和赔率，没有四套平行脚本需要同时记住。

例如，原有部分门槛写的是“库存**大于**赌注”。测试包括余额恰好等于赌注的情况，不能为了方便改成“至少”。20,258 项原／新原生执行比较覆盖轮盘下注与落点组合、保险结果、软 A 调整、庄家槽位、资金变动及音效顺序。原作 172 个决议、163 个理念、10 个事件、5 个窗口、314 个精灵均有对应；对只在自动任务或其他入口引用的定义单独核对。

部分原始菜单键在同一语言内有两份不同译文。重写版明确使用赌场主菜单版本，同时以独立键保留另一份文字；无法保证与任意原安装碰巧选中的文字逐字相同。检查中没有启动 HOI4，界面投影不能代替游戏截图。
