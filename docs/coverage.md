# HOI4 Modding Wiki 功能覆盖

这份清单按模组作者实际工作的主题组织，连接 Wiki 页面、当前公开 API、原生输出位置、教程和测试证据。它覆盖归档 Wiki 的主题族，并补充所用 CWT 快照中较新的特殊项目、突袭、现代学说、阵营和集合系统。单个效果与条件的完整签名位于 [自动生成的命令目录](api/commands/index.md)。

## 如何理解支持层次

| 层次                    | 实际保证                                                                          |
| ----------------------- | --------------------------------------------------------------------------------- |
| 语义 API                | 针对该功能的命名 API、专门的类型/降级规则与测试；边界栏说明未建模部分             |
| CWT 结构校验            | 从指定 CWT 规则生成的领域字段、原生路径和结构检查；规则投射仍有明确限制           |
| 有序原生结构            | 能迁移和重建顺序、重复键、运算符与目标路径，不声称理解全部游戏字段                |
| 原生文件工作流          | 按字节保留资源，检查已建模格式、路径、引用或地图关系；不生成美术或运行 Lua/shader |
| 版本条件                | 只对支持该系统的目标游戏版本有效                                                  |
| 游戏硬编码 / 非编译内容 | 明确属于游戏进程、调试工具或开发流程，不虚构可写入模组的替代 API                  |

同一主题可以同时使用多层。例如创建国家包含国家历史 API、原生标签与颜色定义、军队数据、旗帜和本地化。`DataFile` 或有序包装器本身不能证明某个主题已经拥有完整高层语义；任何格式的成功构建也不等于游戏内行为已经验证。

## 来源与更新方式

本轮核对日期为 2026-11-02。官方 Wiki 的直接访问返回 HTTP 401，因此用 [Wiki 内容的归档目录](https://github.com/thelight0211/hoi4-wiki) 定位主题名称，再以仓库源码、可执行测试、用户本机提供的游戏文档和 [CWTools HOI4 规则](https://github.com/cwtools/cwtools-hoi4-config) 核实格式与机制。归档只负责主题发现，不被描述为已经在线核验的最新 Wiki；各表仍链接官方主题入口。

CWT 快照来源与 SHA-256 见 [API 命令目录](api/commands/index.md)。游戏和大型模组原始文件不会发布到仓库。`docs/coverage-inventory.json` 保存每个主题的规则来源、API 与测试名称，`npm run docs:coverage` 检查引用并确认下表与清单一致；变更支持层次时需一起更新测试和教程。

## 验证完成的含义

普通 CI 检查可分发的合成用例、完整教程、示例构建和安装包。真实原版、Kaiserreich、TNO 的大型语料使用本地输入和单独报告；它们证明的是报告列出的解析、导入、编译、重建或外部规则检查层次。事件何时触发、地图是否可通行、界面布局、AI 策略以及 DLC 行为仍需在匹配版本的游戏中验证，具体流程见 [验证与兼容性](validation.md)。
